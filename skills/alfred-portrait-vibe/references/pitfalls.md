# 毛病对照表：看到什么，多半因为什么

代码逻辑没问题不构成任何证据。渲染出来的画面几乎总有第一轮看不出的毛病。这份表按「看到的现象」索引，比按「应该怎么做」写的规则更好用。

## 看图逐条对

先看总览联络表，再对可疑镜头看原尺寸单帧，最后对每个转场看连续帧。

| 看到什么 | 多半因为 | 改法 |
| --- | --- | --- |
| 主体小小地缩在中间 | 尺寸按「画得下」定的 | 主体占画面宽六成以上，最小可辨单元 ≥20px，反推缩放 |
| 遮住字幕就认不出画面是什么 | 画成了抽象记号 | 加体积与材质（明暗/高光/厚度），或从一个人人认得的画面推进去；还不行就换形象 |
| 字幕说的名词，屏上找不到 | 分镜漏了 | 画出来，或改句子。开场最容易犯 |
| 一大片发白、发糊 | 实心大色块吃掉了辉光 | 有体积的实物画在不参加辉光的底层；或这段把辉光强度调低 |
| 渐变上有一圈圈硬边 | 半透明叠层太少 | 多叠几层、每层更淡，或直接用径向渐变 |
| 东西是平的，像贴纸 | 没有明暗 | 靠边压暗、受光面提亮、背后垫一层极淡的底 |
| 小字压在主体上 | 标注随手放 | 拉到主体外，细引线连过去；一镜最多一条小字 |
| 线条或物体伸进字幕带 | 推近时带进来了 | 该区域元素随景深淡出；字幕带保持干净 |
| 一句字幕里画面变了三四处理 | 贪多 | 拆成两句，或删掉次要变化。每句只改一处 |
| 连着几句画面完全没变 | 没设计「那一处变化」 | 回分镜表补；但结论/引文句停住是合法的，别误伤 |
| 转场中间有几帧说不清在干什么 | 两个状态硬插值 | 换成一个叫得出名字的动作（钻进去/拼起来/倒放回去），或把转场压到半秒内 |
| 推近镜头先漂移后猛冲 | 缩放线性插值 | 缩放在对数空间插值，焦点按 1/缩放 走 |
| 和参考片并排看，自己的又暗又空 | 主体不亮不大 | 主体放大、给颜色和体积；背景可以暗，主体不能暗 |
| 一秒里两样东西同时在动 | 没有主次 | 每一刻只有一个主体在动，其余降到三成亮度或离场 |
| 关键数字被圈注/荧光笔/字幕挡住 | 图层顺序或位置 | 单位必须完整可读，宁可挪标注也不缩字 |

## 时间线与渲染

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 静帧看着正常，渲染出来不对 | 同一属性上两段动画时间重叠 | 前一段结束再开始下一段；不同属性可以并行（x 做视差、y 做浮动） |
| 某个元素从第一帧就在错的位置 | 后一个 `fromTo` 立刻生效了 | 只有作用在同一属性上的第一个动画才立即渲染，其余显式关闭 |
| 某个元素完全不动 | 元素 id 重复，动画打到了另一个同名元素 | 渲染前扫一遍 id 唯一性 |
| 画面跳到某一时刻和连续播放不一致 | 依赖了实时时钟或自运行动画 | 所有状态由当前帧求出；Canvas 用 `seek(t)`，Remotion 用 `useCurrentFrame()` |
| 同一帧渲两遍结果不同 | 随机数没固定种子 | 所有随机来自带种子的发生器——这是「只重渲一段」的前提 |
| 预览和导出不一致 | 字体/素材在导出时还没加载完 | 字体、音频、视频、图片加载完成后再采样 |
| 交付文件特别大 | 编码参数按无损出的 | `-c:v libx264 -preset slow -crf 19 -pix_fmt yuv420p -c:a aac -b:a 256k -movflags +faststart` |

## 声音

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 动作声比画面慢半拍 | 音源开头有静音，按文件起点对齐了 | 量音源内的语义落点：`播放起点 = 目标事件时间 − 语义落点 − 实测输出偏移` |
| 音乐盖住旁白 | 只保证了整体响度 | 语音优先，音乐按场景衰减；先保证可懂 |
| 一串小动作听起来像噪声 | 每个动作都配了一条完整长尾 | 高密度小动作合并成一段；保留必要安静 |
| 削波 | 增益拉太高 | 峰值留到 −1dB 以下；`qa.py` 会报 ≥−0.1dBFS |
| 纯字幕片听着空 | 没有声音设计 | 让声音帮助感知变化与空间，不是补一层 BGM 了事 |

## 实测发现的坑（本技能工具层）

这些是在这台机器上真跑出来、不是推测的：

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| **`beats.py` 八度错误** | 用 `bgm.py` 合成 77 BPM，`beats.py` 测出 154 BPM，小节线全部翻倍 | 检测器偏好中心在 120 BPM。**自己合成的配乐必须 `--bpm`**；看到 >140 或 <90 的警告就复核 |
| **`qa.py` 原本只打印 `ok`** | 旧版不判定规格和时长，跑完看着成功 | 已重写为闸门：规格/时长/音轨/黑帧/削波逐项 PASS/FAIL，有 FAIL 退出码 1 |
| **`sfx-source.py` 不存在** | 原文档让人去定位这个脚本，全盘没有 | 音效检索没有现成脚本；按实际可用的工具做，不假装已装 |

## 终检三遍

全片渲完后按这个顺序过，每次只看一件事：

1. **静音、遮住字幕看一遍** —— 每一段在讲什么，看得出来吗？
2. **只读字幕看一遍** —— 通顺吗？有哪句的名词在屏上找不到吗？
3. **对着联络表和锚点帧看一遍** —— 切点对不对、关键信息有没有出安全区。

不合格的时间点列成清单（镜头 ID + 时间点 + 看到什么 + 要改成什么）。修复后在**相同时间点**重截对比，确认修好了且没改坏别处，再出全片。

## 数字纪律

屏上出现的每个数字，先由代码算出来或从来源查到，再写进文案。禁止先写个好看的数再倒推。

- 「掷了一万次」的计数器就要真数到一万：载入时用固定种子把整场模拟算完存成表，每帧查表回放。
- 模拟数据在画面上标「模拟」或「示意」，示意曲线标「示意」。
- 结论数字来自计算。文案里的数字与计算结果不符时，**改文案，不改数据**。

## 交片诚实条款

交付时如实说明：还有哪些不满意、哪些段落没逐帧看过、哪些数字是示意。宁可在交付说明里列三条待改，也不要让观众发现一条。

`qa.py` 打印的「闸门通过」只代表能算的项目都过了。机器过检 ≠ 可以交片。
