# 生成素材：按分镜定向制作

## 先判断需要生成什么

逐镜明确素材角色：人物表演、场景、动作镜头、独立旁白、插画或背景。使用现有素材更合适时直接用，避免为“用了 AI”而重做全部画面。

确定这一镜的构图、主体占位、镜头动作、表演和字幕空间，再写请求。让生成素材适配合成需求，而不是生成后再用大量遮罩修补冲突。

复现同一人物、产品或地点时，确定参考和连续性关系。先验证一张关键形象或一小段表演，再扩展关联镜头。文本、精确数据和细 UI 优先在合成层制作。

## 生成与声音

### 用户选择配音

用户给出文案后无需等待文案或目标确认，即可在完整配音和精确分镜之前提供试听；可以与首个分镜的四张代码模板同轮展示。挑选四个差异明确且当前服务确实可用的声音，编号 1/2/3/4，对用户文案的同一段约 10–15 秒内容试读，尽量统一语速、音量和处理，方便比较音色与表达。服务目录、voice ID 和可用能力以实际连接的工具/官方资料为准，不编造声音名称或样音。

展示编号、实际可播放音频、音色特点和适合的表达；请用户选编号，并提出语速、情绪、停顿或读音修改。用户可要求补一轮候选或使用自己的录音。先选声音，再生成全文，避免无谓地为每个候选都生成整段。

用户确认选声后才生成完整配音，全文音频再让用户确认。记录所选服务、声音标识、参数和版本；以这版实际录音确定每镜时长。配音未确认前只写画面意图与粗分镜，不锁定镜头秒数。

保留仍有效的样音与已接受全文片段，按制作指南核对缓存输入；文案、模型、音色参考或语速等改变时只重做受影响的自然语义段，并更新时间表。为了缓存不把每句话强行割裂合成，不把旧时长套到新音频。

样音和全文生成沿用已有付费授权范围。缺少可播放样音、服务或不足四种真实声音时说明具体缺口，不能以文字风格描述或重复样音凑数。明确无人声的项目可以跳过这两次声音确认，仍需确认阅读与动作时长。

### Breeze TTS2：优先配音引擎

使用 Breeze TTS 2；优先复用已有 Breeze 服务、账户和输出，不因添加此能力自动下载权重或部署 GPU 环境。官方云 API 与开源推理服务是不同协议，接入前确认实际服务类型、模型版本和可用权限。用户指定此引擎后，缺少接入时说明具体缺口，不自行替换。

**官方托管服务：** 使用用户已配置的 `BREEZE_API_KEY` 或现有安全凭据渠道；官方 API 根为 `https://api.breeze.blue/v1`，鉴权头为 `xi-api-key`。先查询实际可用模型/声音，选择当前列出的 Breeze TTS 2 对应型号（如基本型或 multilingual），不假定所有账号和接口共用一个 model_id；参数以当前官方文档为准。记录状态和配置引用，不将密钥写入计划、日志或交付包。

- 有四个适合题材的既有声音时，使用实际 voice_id 进行同文试读；否则通过 Voice Design 设计四个有区别的声音。描述可覆盖沉稳、亲切、清晰、富表现力等方向，按文案调整，不固定为四个不存在的官方预设名。
- 官方 `POST /voice-previews/design` 的 `preview_count` 目前单次范围为 1–3。四种方向分别使用 `preview_count=1` 请求，保持相同试听文案；不要提交不支持的 `preview_count=4`。保留每份实际音频及其 `generated_voice_id`。
- 用户选中设计试听后，用 `POST /voice-previews/{generated_voice_id}/save` 保存该声音，提供 `voice_name` 和真实 `language_code`（中文通常为 `zh`），取得 `voice_id`。后续全文与重录复用此 ID；既有声音直接复用其 ID，不重复保存。
- 全文优先用带时间戳的 TTS 接口 `POST /text-to-speech/{voice_id}/with-timestamps`，保留返回的 `audio_base64`、`content_type` 和 `word_timestamps`，按实际格式解码音频。核查时间单位及与音频的对应关系，再转换成句子/分镜事件；其他部署的字段与粒度按实际协议处理。
- 官方时间戳接口默认单次文本上限为 1000 字符，更高限额取决于账户，按当前限制分自然语义段合成。逐段复用同一声音，以实际拼接位置为各段时间戳加全局偏移，并处理停顿。返回 202 时保存任务 ID 并查询进度，不因尚未收到音频重复提交同一生成请求。

**已有自托管服务：** 按所部署版本的官方推理说明接入。官方 PyTorch 服务的 `/v1/audio/speech` 与托管云 API 路径/返回不同；其流式输出为 24 kHz、单声道、16-bit little-endian PCM，需要正确封装为可播放 WAV 或转码。选声后保存已接受样音与准确转写作为后续参考，按 Voice Clone/Voice Direction 保持音色；未提供时间戳时另做对齐并核对。

四份试听只生成实际所需短段。沿用用户的付费账户和预算范围；没有额度/服务时报告缺口，继续制作代码首镜候选。商用任务选择部署方式前核对实际许可：官方开源模型及自托管输出受研究/非商业许可约束，托管付费输出的商业使用按其条款处理。

只在实际用到对应操作时读取以下官方资料：

- [API 接入与鉴权](https://docs.breezeblue.ai/api-reference/introduction)
- [设计试听与候选数限制](https://docs.breezeblue.ai/api-reference/voice-previews/create-design-previews)
- [保存选中的试听声音](https://docs.breezeblue.ai/api-reference/voice-previews/save-voice-preview)
- [生成配音与时间戳](https://docs.breezeblue.ai/api-reference/text-to-speech/convert-with-timestamps)
- [官方开源推理、参考声音与许可](https://github.com/breezeblue-ai/breeze-tts)

### 按已确认声音制作

- 图像请求写清外观、材质、光线、构图和参照关系；视频请求另写实际动作、表演和相机行为。
- 旁白沿用用户选定的音色、语速、情绪和断句。接受的实际配音或表演决定逐镜时间；不要按字数猜秒数后强行塞入。
- 用关键语句、揭示和动作定义语义事件，再将它们对到被采用的录音或视频。文案或表演变化后，重新核查受影响的事件和后续时间。
- 独立旁白、画内人物声、环境声和音乐分清来源与作用，合成时决定保留、衰减或混合。
- 优先使用已连通且符合任务的服务和已生成素材。付费执行遵守用户已有预算、账户和范围；缺少支出授权时先给出具体生成计划和估计，不把“已接入账户”当成任意消费授权。

项目保留素材来源、采用版本、关联参考和必要提示词。复用已接受的生成结果；重试或修改只处理受影响的请求，保留仍适用的输出。

## Hypit 是可选工具，不是所有视频的基础依赖

普通代码动画、已有录屏剪辑和知识可视化无需启动 Hypit。只有生成/表演流程确实受益，或正在续做 Hypit 工程时才进入其 Runtime。

从会话给出的目录或用户目录 `.agents/skills/hypit`、`.codex/skills/hypit` 定位实际技能。先读 `references/environment/distribution.md` 的定位方法，检查 `hypit version`、`hypit paths` 或现有包记录；安装 skill 本身不代表 CLI、模型账户和额度已就绪。

按当前动作只读相关文档：

| 当前动作 | Hypit 相对资源 |
| --- | --- |
| 判断服务连接与能力缺口 | `references/environment/model-and-provider.md` |
| 写图像请求 | `references/playbooks/craft/image-direction.md` |
| 选声音与写视频请求 | `references/playbooks/craft/voice-direction.md`、`references/playbooks/craft/video-direction.md` 中相关一份 |
| 理解素材与组件组织 | `references/production/system.md` |
| 写 Sources、Recipes、Runs 并复用输出 | `references/production/authoring.md` |
| 计划、执行、失败后续做 | `references/production/builds.md` |
| 导出或续做原生 Hypit 成片 | `references/production/rendering.md` |

SDK、语法和安装组件以选中运行时的实际文档为准。不得凭记忆发明 SVML/SVS/SVRun 字段或 Provider 接口。运行中断后先查实际任务状态，避免重复提交；复用已有输出需按运行时的选择规则执行。

缺少所需生成服务时继续能独立进行的分镜、合成和素材整理，并明确具体缺口。未经用户同意，不把要求的真实生成镜头悄悄换成占位动画并称作完成。
