# 产品展示：用真实功能支撑镜头

## 先定要证明的价值

从实际页面、交互和代码判断产品能做什么，再选择最能体现价值的动作。把“功能名称”改成可观察的前后变化：输入了什么、执行了什么、得到了什么。

真实功能用实际界面截图或交互录屏表达。概念开场和品牌段可以创作独立图形，避免让人将设计稿或虚构结果误认为已实现的功能。

## 采集与视觉

- 优先使用公开演示、测试或脱敏状态。在采集前处理不应入片的个人、客户或内部信息；保留演示所需的功能证据。
- 提取产品字体、字号层级、间距、圆角、表面和强调色，作为视频的视觉依据。借镜头结构，不直接套别人的品牌外观。
- 等待字体、图片和目标交互稳定后采集。根据实际推近比例选择纹理分辨率，避免采集低清画面后靠放大补救。
- 需要逐元素动效时，采集全页背景、必要元素切片和坐标。`layout.json` 记录 CSS 像素中的 `{x,y,w,h}` 及 viewport、deviceScaleFactor；绘制时统一坐标，别混用截图物理像素。
- 有真实操作过程就保留关键步骤和结果；真实录屏、冻结截图、创作图形各自承担适合的镜头。

## 运镜与节奏

一个镜头有一个明确主角和动作弧：观众先找到主体，再看它变化，最后读懂结果。推近用于看细节，环绕用于看空间关系，堆叠用于看数量或组织；没有表达作用就用更简单的运动。

重要结果落定后留出可读时间。细小按钮、整页文字和大幅运动不要同时竞争注意力。全片可以复用统一语法，不机械要求每种动效只能出现一次。

强节拍宣传片才按音乐分析节拍和重音；讲操作、对比和解释时，信息理解优先。真实页面上的文字是证据，不在片中另造与它冲突的文案。

## 按需调用现有 Shotcraft 库

优先使用会话里公布的 `video-shotcraft` 目录。未给出时检查当前技能同级 `../video-shotcraft`，再检查用户目录 `.codex/skills` 与 `.agents/skills`。检查实际存在后再引用。

| 需要什么 | 相对该库的资源 |
| --- | --- |
| 查指定镜头或变体 | `gallery/api/library.json` |
| 镜头配方、命门参数、准确 demo 路径 | `references/shots/` 中对应卡片 |
| 页面采集脚本 | `assets/scripts/capture-template.mjs` |
| 明确要求复用 Ink Press | `template/TEMPLATE.md` |
| 查动作声、下载或分析音效 | `references/sfx-sourcing.md` 与 `assets/scripts/sfx-source.py` |
| 精细声音对齐 | `references/sound-design.md` |
| 强节拍网格与回测 | `references/music-beat-sync.md` |

指定镜头先用索引校验名称和变体，再读卡片及其准确 demo；不要凭名字重写已有精调实现。只借用实际要用的卡片或脚本，不导入全套画廊、例片、发布工具和模板工程。

复用文件前看依赖、授权及相对资源位置，将实际需要的文件放入视频工程。库缺失时可原创实现，明确哪些镜头没有使用原库，不声称精确还原已有卡片。
